# ORBIT-Q updated benchmark results for paper writing

This directory is the paper-facing summary of the ORBIT-Q results collected in
the benchmark and expert-optimization branches. It is deliberately separate
from the benchmark runner: runner artifacts remain the provenance source,
while this directory provides a compact, reproducible set of tables, figures,
captions, and take-home messages.

The figure logic follows the public [ORBIT-Q repository](https://github.com/sxzgroup/ORBIT-Q)
and the paper's task-level and resource views in [arXiv:2607.03105](https://arxiv.org/abs/2607.03105):
agent validity, task-level outcomes, solving-side resources, and artifact
runtime are reported as separate layers. A runtime speedup is never silently
treated as an agent-resource comparison.

### Adjudication rule that matters

The benchmark reward is preserved exactly in the source table, but the paper
matrix applies the final human-expert review used for the comparison. In
particular, Task 08 is **F** for Sol high, Sol ultra, Terra high, Luna high,
DeepSeek high, and DeepSeek max. Luna and Sol ultra retain their raw verifier
reward in the provenance columns, but those raw passes are not counted as final
paper-valid solutions. This prevents a reward/audit artifact from being
mistaken for acceptance under the reviewed expert reference.

## Human-expert optimization results

The complete 12-task table is in
[`source_data/expert_optimization.csv`](source_data/expert_optimization.csv).
The largest end-to-end gains are:

| Task | Optimized strategy | Baseline → optimized (s) | End-to-end speedup |
|---:|---|---:|---:|
| 07 | Classical ancilla / duplicate-trajectory reduction | 140.076 → 3.071 | **45.758x** |
| 05 | Exact bounded-rank no-QR MPS | 97.084 → 6.898 | **14.076x** |
| 01 | Batched closed-form gate construction | 60.651 → 6.360 | **9.636x** |
| 10 | Native hyperedge with fixed contraction path | 18.931 → 3.869 | **4.898x** |
| 03 | TensorCircuit `K.vmap` local conditional maps | 4.260 → 0.871 | **4.894x** |
| 12 | Batched fixed-order Padé SU(4) construction | 9.083 → 2.321 | **3.914x** |
| 09 | Preconstructed causal cones and compiled trajectory | 33.504 → 8.767 | **3.822x** |

Tasks 02, 04, 06, 08, and 11 are retained in the full CSV even when their
end-to-end effect is modest. Task 11's 81.215x isolated onsite-term factor
is explicitly not reported as an end-to-end speedup; its full measured gain is
1.464x. Task 08 has no confirmed improvement because its confidence interval
crosses 1x.

## Mechanistic insights

- **Task 03 loophole.** Post-selection after every brickwork layer leaves six
  independent one-qubit survivors. The exact product-state reduction is the
  source of the large speedup; requiring the complete even+odd block before
  post-selection removes this shortcut.
- **Task 07 loophole.** The measured ancillas act as an analytically sampled
  classical controller with only two unique branches (weights 63/64 and 1/64).
  Merging duplicate trajectories is an exact design reduction, not an
  approximation.
- **Task 10.** The useful change is cold specialization and fixed contraction
  planning, not an intrinsic MPO gate arithmetic advantage. Native hyperedge
  with a fixed path gives 4.898x end to end; fixed-path hyperedge versus fixed
  MPO is only 1.011x.
- **Task 05.** Exact bounded-rank, no-QR MPS contraction removes the dense-state
  bottleneck. The TensorCircuit-native fused alternative is secondary.
- **Task 09.** Explicit causal-cone pruning plus compact TensorCircuit graphs
  removes irrelevant global work without exploiting a challenge loophole.
- **Task 12.** A fixed-order, batched Padé SU(4) kernel shrinks the
  differentiated gate-build graph.

## Resource and provenance notes

The six GPT-5.6/DeepSeek agent runs use Harbor Docker isolation, the common
TensorCircuit-NG task image, six CPUs, 10,240 MiB memory, and 16,384 MiB
storage. Each task is run sequentially and contributes at most one valid final
outcome. The solver/auditor specifications are recorded in the corresponding
benchmark branches; this report uses GPT-5.6 Sol high as auditor for Terra,
Luna, and DeepSeek runs where applicable. Agent wall time and token/cost fields
are solving-side measurements, not artifact runtime.

Fable 5 is a separate Cursor/Fable workflow. Its 12/12 artifact result is
useful as a reported benchmark point, but its harness resources and costs are
not compared to the Docker-agent runs.

This is a one-trial-per-model/effort/task comparison. Provider pricing,
hardware, and model-service latency should not be interpreted as a universal
hardware-independent ranking. The source files preserve missing values
instead of fabricating them.

## Suggested paper paragraph

Across the 12 public quantum workloads, GPT-5.6 Sol reached 10/12 valid
artifacts at both high and ultra effort, Terra reached 9/12, Luna reached
9/12 after final expert review, and DeepSeek V4 Flash reached 5/12 at both
high and max effort. The separate Fable 5 workflow reported 12/12 artifacts,
but its resource measurements are not comparable. Optimizing the human
TensorCircuit-NG references exposed two exact task-design reductions (Tasks
03 and 07) and several framework-native improvements; the largest measured
end-to-end gains were 45.758x and 14.076x. These results motivate reporting
validity, artifact runtime, and agent resources as separate axes.
