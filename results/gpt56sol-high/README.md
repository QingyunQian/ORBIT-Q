# GPT-5.6 Sol High — TensorCircuit Benchmark

This directory contains one Harbor trial for each of the 12 ORBIT-Q
TensorCircuit challenges.

## Protocol

- Run date: 2026-07-28
- Base commit: `0201238ec2983907e2891f5319f5fff2d00844d5`
- Solver agent: Codex
- Solver model: `gpt-5.6-sol`
- Solver reasoning effort: `high`
- Audit model: `gpt-5.6-sol`
- Audit reasoning effort: `high`
- Framework: TensorCircuit-NG / `tensorcircuit-nightly`
- Docker image: `challenge-benchmark-quantum-tensorcircuit:py311`
- Trials per challenge: 1
- Harbor retries: 0

The solver and audit effort are both fixed at `high` to match the original
GPT-5.5 benchmark effort. Challenges were run sequentially.

Canonical files under `tasks/` were not changed. The Mac runner used temporary
task copies with only the resource declaration adapted to 6 CPUs, 10,240 MiB
memory, and 16,384 MiB storage so Harbor could run against the local Colima
backend. This resource adaptation can affect wall-clock runtime comparisons.

## GPT-5.5 comparison

![GPT-5.5 versus GPT-5.6 Sol high](figs/gpt55-vs-gpt56-comparison.png)

Using the paper's agent-axis definition, GPT-5.5 high passed 10/12 tasks with
a 2.197x geometric-mean artifact slowdown on its passed tasks. GPT-5.6 Sol
high passed 10/12 tasks with a 1.428x geometric-mean slowdown on its passed
tasks. Thus the two runs have the same validity count, while the GPT-5.6 Sol
high valid artifacts are about 35% closer to the expert runtime baseline by
this aggregate metric.

The GPT-5.6 expert references were executed only after all candidate files had
been frozen and committed. They were run without reading their source, in the
same local image and Colima resource envelope as the GPT-5.6 candidates.
Challenge 08's expert reference requested an 18,047,205,376-byte JAX buffer
and could not run under the 8 GiB Colima limit; task 08 failed the GPT-5.6
audit and is excluded from the passed-task geometric mean regardless.

This is not a fully controlled model-only comparison. The GPT-5.5 paper run
and GPT-5.6 run used different hosts and benchmark revisions, and the new run
uses GPT-5.6 Sol high for semantic audit rather than the paper's GPT-5.5 audit
plus human adjudication. Each slowdown ratio is same-machine within its own
run, which reduces but does not eliminate those confounders. Exact data and
provenance are in `runtime-comparison-mac.json`; the figure is generated by
`tools/make_comparison_figures.py`.

## Challenge 05 audit adjudication

The original GPT-5.6 Sol audit rejected challenge 05 because it claimed that
TensorCircuit `exp1` implements `exp(-i * theta * U / 2)`. That API claim is
incorrect for the pinned `tensorcircuit-nightly==1.8.0.dev20260726` image.
`exp1` defaults to `half=False` and implements `exp(-i * theta * U)`; only
the named rotation gates such as `rxx` and `rzz` opt into the half-angle
convention. Therefore `theta=1j*a` and `theta=1j*b` implement exactly the
required `exp(a*X)` and `exp(b*ZZ)` filters.

A direct container check found Frobenius errors of `2.77e-08` and `5.88e-08`
against `exp(a*X)` and `exp(a*ZZ)`, while the errors against the incorrectly
claimed half-angle matrices were `0.145` and `0.205`. The candidate otherwise
matches the ten-layer circuit, normalization, optimization, history, and return
requirements. Its final audit score and reward are therefore adjudicated from
0.0 to 1.0. Exact evidence is in
`challenge-05/audit-adjudication.json`.

The original `audit-details.json` and `job-result.json` are preserved unchanged
as raw Harbor provenance. `reward.json` is the final machine-readable score and
records both the original and adjudicated values. The other eleven audit
decisions were source-reviewed; no other clear misclassification was found.
Challenge 08 remains failed because its fixed Sobol design produces correlated
quasi-samples rather than independent circuit shots.

## Final audit failures

- Challenge 01: the candidate applied an MPS bond-dimension cap after each
  two-qubit gate. The audit considered this unrequested truncation a change to
  the specified unitary circuit.
- Challenge 08: the candidate drove conditional sampling with a fixed scrambled
  Sobol sequence. The audit rejected these correlated quasi-Monte Carlo rows as
  a substitute for independent circuit shots and as evaluator exploitation.

The full audit rationale is retained in each challenge's
`audit-details.json`.

## Solver timeouts

Challenges 01 and 06 reached Harbor's solver time limit after writing their
candidate files. Harbor still ran the verifier on those candidates. Challenge
01 received reward 0.0 due to the audit failure above; challenge 06 passed all
three reward components and received reward 1.0.

## Agent-side resource use

![GPT-5.6 Sol high agent-side resource use](figs/gpt56sol-high-agent-resource-use.png)

The figure follows the agent-axis resource accounting used by the paper's
Figure 4. Agent wall time includes only Harbor's `agent_execution` interval;
environment setup and verifier time are excluded. The run used 3h 17m 41.7s
of agent solve time and 26.071 million total solving-side tokens, comprising
1.709 million non-cache-read input tokens, 24.199 million cache-read input
tokens, and 0.163 million output tokens.

Across the ten final reward-passing tasks, the aggregate cost was USD 2.55 per
valid solution and agent solve time was 19.77 minutes per valid solution.
Marker area in panel (c) is proportional to the total recorded solver cost.
For comparison, the paper reports USD 1.80 and 12.52 minutes for GPT-5.5
high, or USD 1.33 and 8.91 minutes for GPT-5.5* high with the TC performance
checklist. Thus this GPT-5.6 Sol high run used more agent-side resources even
though its passing artifacts were faster relative to the expert runtime
baseline. Costs are Harbor's recorded model-service estimates and are not
normalized to a common provider price schedule.

Exact task-level data and provenance are in `agent-resource-use.json`; the
figure is generated by `tools/make_resource_figure.py`.

Each challenge directory contains:

- `solution_N.py`: candidate produced by the solver;
- `functional-stdout-official.txt`: official functional evaluator output;
- `reward.json`: final machine-readable scores, including adjudication metadata
  where applicable;
- `audit-details.json`: original static, functional, and Codex audit details;
- `job-result.json`: original Harbor aggregate result;
- `stamp-info.json`: model, effort, trial, resource, token, cost, and
  adjudication metadata.

Challenge 05 additionally contains `audit-adjudication.json`, which records the
false-negative correction and its reproducible TensorCircuit API evidence.

Harbor's artifact sanitizer replaced the ordinary `true` identifier fragment
in four places in the collected challenge-04 candidate. The archived
`solution_4.py` restores those four unambiguous identifiers
(`true_probabilities`, `true_p01`, and `true_p10`) so the saved candidate
matches the valid source that ran inside the verifier container. Verifier
outputs remain verbatim.

The verifier-side sanitizer also renders some affirmative booleans as the
literal token `[REDACTED]` in `audit-details.json`. Those files are retained
verbatim for provenance but are therefore not strict JSON. Machine-readable
scores are in `reward.json`.
